# Amber 1.0.0

**Maintain the legacy SQL nobody wants to touch.**

Amber is an offline-first desktop app for the SQL scripts you inherited: thousands of lines of procedures, temp
tables and batch steps written by many hands. It shows what a script does, where every column comes from, and whether
your change is safe. It never runs your SQL, and your scripts stay on your computer.

▶ Tutorial video (under 3 min): https://paganini2008.github.io/amber/#tutorial

## Highlights

- **8 databases, each with its own grammar.**
  - Oracle, SQL Server, PostgreSQL, MySQL, MariaDB, Db2, H2 and SQLite.
  - Strict parsing, with a fallback that still reads broken or partial scripts.
- **Understand a script.**
  - An outline with a one-line summary of every statement.
  - Query structure as nested boxes, and the logical execution order (FROM → WHERE → GROUP BY → SELECT …).
  - Execution playback, object lifecycles, and the data flow between steps.
- **Column and variable lineage.**
  - Across CTEs, subqueries, temp tables, procedures and functions: call arguments are mapped to parameters, and
    RETURN values are followed.
  - Columns written without a table or alias are placed from evidence elsewhere in the same script (INSERT column
    lists, qualified uses, UPDATE … SET). Such placements are marked *inferred*.
- **Inferred ER diagram.**
  - Relationships come from joins, declared foreign keys, metadata and naming.
  - Each one shows its cardinality and confidence and links back to the statements behind it.
  - Exports to SVG, PNG and Mermaid.
- **Risk findings with verified quick fixes.**
  - 27 rules across risk, performance, maintainability and info.
  - Each rule can be switched on or off and given a different severity.
- **Suggestions.**
  - One tab with every finding, grouped by statement: what Amber can fix itself, an optimized version of each
    statement, and what needs the AI or a manual change.
  - Fixes that keep the result the same can be applied at once; one that changes behavior in an edge case opens a
    review you have to confirm.
- **Refactor script, offline.**
  - Applies, pass after pass, every rewrite proven to keep the result the same for any data: always-true `1=1`,
    sorts nothing uses, `SELECT *` with known columns, UNION → UNION ALL where no duplicates can occur…
  - Then compares the whole script before and after: conditions, literal values, source tables, output columns and
    lineage must be unchanged. The result opens in Change impact; nothing reaches the editor until you apply it.
  - Rewrites that state a condition differently (NOT IN → NOT EXISTS, a function on a column → a range) are offered
    one by one, never applied by a refactoring.
- **AI suggestions (optional).**
  - Works with Ollama or any OpenAI-compatible endpoint.
  - The context is built locally, names and literals are masked, and you can add your own notes.
  - *Fix with AI* and *Refactor with AI* per statement. Every rewrite is checked by the engine; Apply appears only
    when it finds no difference in the logic.
- **Change impact.** Compares two versions of a script by meaning, ranked by risk.
- **Find references** and a **handover document** (Markdown or HTML).
- **Online mode (optional, read-only).**
  - Connects to several data sources at once and reads catalog metadata only.
  - Inferred results then become certain.
  - No JDBC driver is bundled. Each one is downloaded on demand from Maven Central (or an HTTPS mirror) when a
    connection needs it, after Amber shows the vendor's license, and is checked against a pinned SHA-256.
- **Updates.** Amber checks GitHub Releases when it starts (it can be turned off in Settings). On Windows and Linux
  (.deb / .rpm) a newer version is downloaded in the background and installed on restart; on macOS Amber links to
  the download page.
- **Interface.**
  - English, 简体中文 and Español, including the engine's own explanations.
  - Light and dark themes, database icons, icon tabs.

## Downloads

| System | File |
|---|---|
| Windows x64 | `Amber-windows-x64-setup.exe` |
| macOS (Apple silicon) | `Amber-macos-arm64.dmg` |
| macOS (Intel) | `Amber-macos-x64.dmg` |
| Linux x64 | `Amber-linux-x64.deb` / `Amber-linux-x64.rpm` |

`SHA256SUMS` lists the checksums. A Java runtime is bundled, so there is nothing else to install.

The installers are not code-signed:

- **macOS:** the first time, macOS says Amber cannot be opened. Go to *System Settings → Privacy & Security* and
  click *Open Anyway* next to Amber, or run `xattr -dr com.apple.quarantine /Applications/Amber.app`.
- **Windows:** choose *More info → Run anyway*.

## Quality

- **Engine tests:** 547 unit tests, plus integration tests:
  - a corpus of 790 public grammar test files;
  - mutation fuzzing of every engine method;
  - scale tests (1 MB lines, 20,000 statements);
  - protocol abuse tests.
- **Coverage:** line coverage of at least 90 % is enforced.
- **Builds:** the engine is compiled for Java 17 and built, tested and shipped with JDK 25.
- **Online metadata:** verified against Oracle, SQL Server, PostgreSQL, MySQL, MariaDB and Db2 servers.

## Build from source

JDK 17+ and Node 22:

```
mvn -f backend/pom.xml install
cd ui/amber-desktop && npm ci && npm run dev
```
