The keyword tokens in `H2Lexer.g4` and the `non_reserved_keyword` rule in `H2Parser.g4` are
generated by `backend/amber-core/tools/h2/generate_keywords.py`; to reserve or un-reserve a word,
edit `RESERVED` in that script and re-run it.

Known gaps (see the corpus in `amber-core/src/test/resources/corpus/h2/amber` for what is covered):

- Words in `RESERVED` (including `LIMIT`, `MINUS`, `THEN`, `LATERAL`, `ROLLUP`, `CUBE`, `UNBOUNDED`)
  cannot be unquoted identifiers; `SET NON_KEYWORDS` is not modelled.
- Aliases without `AS` cannot be `KEY`, `AT`, `ESCAPE`, `FILTER`, `FORMAT`, `IGNORE`, `OVER`,
  `RESPECT`, `USE`, `WITHIN` or `YEAR`…`SECOND`.
- `CONVERT(x, DOUBLE PRECISION)` and other multi-word type names inside `CONVERT` do not parse.
- `SET <setting>` and `HELP` arguments are parsed generically; linked-table arguments are a plain
  expression list.
- Undocumented syntax from other databases is not accepted (PostgreSQL `::` and `ON CONFLICT`,
  Oracle `(+)` and `CONNECT BY`, MySQL `INTERVAL 1 DAY`).
- `//` always starts a comment, so `a//b` is not a division; a `$$` string cannot contain `$$`.
